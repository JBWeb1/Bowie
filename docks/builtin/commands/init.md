description: Write a DOCKS.md that teaches Docks how this project works
---
Create (or improve, if it exists) a DOCKS.md file at the project root for future sessions. Explore the
project first: README, package manifests, build and test configuration, folder layout, and a few core
source files. Then write a short, accurate DOCKS.md with:
- what the project is, in two or three sentences
- how to install, run, build, test and lint it (exact commands)
- the layout: which folders hold what
- conventions worth following (style, patterns, naming, testing approach)
- anything surprising or easy to get wrong
Keep it under about 80 lines, and only include things that are true for this project.
